# cctree — Claude Code Session Browser

## Overview

A lightweight **library + CLI** for scanning `~/.claude/projects/` and producing a structured overview of Claude Code projects, sessions, and basic stats. Think `tree` meets `git log` for your Claude Code history.

- **As a CLI:** `cctree` prints a formatted tree or JSON to stdout.
- **As a library:** `import { scan } from 'cctree'` returns typed `ProjectInfo[]` for use in higher-level tools (e.g. an iOS/visionOS orchestrator app, a web dashboard, an Obsidian plugin).

## Installation & Runtime

- **Language:** TypeScript, strict mode, ESM
- **Package manager:** npm
- **Build:** `tsup` with `format: ['esm']`
- **Target:** Single executable via `npx cctree` or global install
- **Minimum Node:** 20+
- **Runtime dependencies:** None
- **Dev dependencies:** `typescript`, `tsup`, `@types/node`

## Data Sources

All data lives under `~/.claude/`. The tool is **read-only** — it never writes anything.

### Primary: `~/.claude/projects/{path-slug}/`

- Path slug is the project directory with `/` replaced by `-` (e.g. `-Users-ward-src-myapp`)
- Session files: `{session-id}.jsonl` (UUID-named, at top level of the project slug dir)
  - **Note:** Not all sessions have a `.jsonl` at the project root. Some older projects only have session directories without sibling `.jsonl` files.
- Session directories: `{session-id}/` containing:
  - `subagents/agent-{hash}.jsonl` — subagent transcripts
  - `subagents/agent-{hash}.meta.json` — subagent metadata
  - `tool-results/{id}.txt` — large tool outputs stored separately

### Fallback: `sessions-index.json`

Some project slug dirs contain a `sessions-index.json` with pre-parsed session metadata. However, this file is **notoriously unreliable** — it stopped being updated around v2.1.31 (late Jan 2026) for many users, and multiple open issues document it failing to index new sessions ([#18897](https://github.com/anthropics/claude-code/issues/18897), [#24729](https://github.com/anthropics/claude-code/issues/24729), [#25032](https://github.com/anthropics/claude-code/issues/25032)).

**The JSONL files are the sole authoritative source.** Only use `sessions-index.json` as a last resort for orphaned sessions — those that exist as session directories but have no sibling `.jsonl` file (e.g. older sessions whose JSONL was cleaned up). The `originalPath` field can also help resolve a project's real directory path when `~/.claude.json` lookup fails.

```json
{
  "version": 1,
  "entries": [
    {
      "sessionId": "9e732690-...",
      "fullPath": "...",
      "firstPrompt": "I rename the repo from vine77/tmp to...",
      "summary": "Git Remote URL Update: Drum-Rack to Tmp Repository",
      "messageCount": 2,
      "created": "2026-02-02T03:46:41.144Z",
      "modified": "2026-02-02T03:46:58.469Z",
      "gitBranch": "claude/ableton-drum-rack-samples-WaP0O",
      "projectPath": "/Users/ward/tmp/drum-rack"
    }
  ],
  "originalPath": "/Users/ward/tmp/drum-rack"
}
```

### Secondary: `~/.claude.json` (at home root, NOT inside `~/.claude/`)

- `projects` map keyed by real directory path, containing per-project metadata
- Used to resolve path slugs back to real directory paths
- **Note:** The config may have many more project entries than `~/.claude/projects/` has directories. Only projects with directories on disk are relevant.
- Key fields per project:
  - `lastSessionId` — UUID of the most recent session
  - `lastCost` — total cost of the last session in USD
  - `lastModelUsage` — per-model breakdown: `{[modelId]: {inputTokens, outputTokens, cacheReadInputTokens, cacheCreationInputTokens, costUSD}}`
  - `lastLinesAdded`, `lastLinesRemoved` — code change stats from the last session
  - `lastAPIDuration` — API time in ms for the last session
  - `exampleFiles` — auto-detected representative files

### Secondary: `~/.claude/sessions/*.json` (Active Session Detection)

PID-keyed JSON files mapping running Claude Code processes to session IDs:

```json
{
  "pid": 27483,
  "sessionId": "5982223b-285e-42d2-84d4-9d855dcf78c0",
  "cwd": "/Users/ward/src/cctree",
  "startedAt": 1773790181348
}
```

Use these to detect **currently running** sessions by checking if the PID is still alive. This enables a true "active now" indicator beyond just "active today".

### Also Present (skip)

- `bridge-pointer.json` — session/environment pointer for remote control. Skip but don't crash on it.
- `tool-results/` directory contents — skip, not needed for session overview.
- `memory/` directories — per-project memory storage. Skip.
- `history.jsonl` — prompt input history. Skip.

### JSONL Entry Types

Each line in a `.jsonl` file is a JSON object. For the indexer, handle these:

|Type                            |What to extract                                                                                                                                                       |
|--------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|`user`                          |`timestamp`, `version`, `gitBranch`, `permissionMode`. Count for message stats. Extract first user `message.content` as `firstPrompt`.                                |
|`assistant`                     |`slug`, `message.model`, `message.usage` (token counts), `timestamp`. Track last model used. `slug` appears here (NOT on user entries).                               |
|`system` subtype `turn_duration`|`durationMs` — accumulate for total session active time. Also carries `slug`.                                                                                         |
|`custom-title`                  |`customTitle` — user-set session name via `/rename`. **Highest priority for display name.** Use the last one found.                                                   |
|`agent-name`                    |`agentName` — named agent for the session. Informational, not used for display name.                                                                                  |
|`summary`                       |`summary` text — conversation synopsis used for context compaction. Use the last one found.                                                                           |
|`pr-link`                       |`prUrl`, `prNumber`, `prRepository`. Collect into array. May appear multiple times per PR (deduplicate by `prUrl`).                                                   |
|`progress`                      |**Skip entirely.** Can be multi-MB streaming noise from subagent updates.                                                                                             |
|`saved_hook_context`            |Skip.                                                                                                                                                                 |
|`file-history-snapshot`         |Skip (not needed for overview).                                                                                                                                       |
|`last-prompt`                   |Skip.                                                                                                                                                                 |
|`queue-operation`               |Skip.                                                                                                                                                                 |

**Session name resolution order:** `customTitle` (from `custom-title` entry) → `slug` (from `assistant`/`system` entries) → first 8 chars of session UUID.

**User entry note:** Skip counting entries where `isCompactSummary === true` — these are compaction artifacts, not real user prompts.

## CLI Interface

```
cctree [options]

Options:
  -p, --path <dir>     Override ~/.claude location
  -n, --limit <N>      Show only N most recent sessions per project (default: all)
  --json               Output as JSON instead of formatted tree
  --project <slug>     Filter to a specific project (partial match on slug or directory)
  -h, --help           Show help
  -v, --version        Show version
```

Argument parsing: use `node:util` `parseArgs` (built-in since Node 18.3). No external arg parser.

```ts
import { parseArgs } from 'node:util';

const { values } = parseArgs({

    json:    { type: 'boolean' },
    project: { type: 'string' },
    help:    { type: 'boolean', short: 'h' },
    version: { type: 'boolean', short: 'v' },
  },
});
```

### Library API (`lib.ts`)

This is the public entry point for programmatic use. Re-exports types and exposes a high-level `scan()` function:

```ts
// src/lib.ts
export type { ProjectInfo, SessionInfo, SubagentInfo, PrLink, ClaudeConfig, SessionsIndex } from './types.js';
export type { ScanOptions } from './scanner.js';
export { scan } from './scanner.js';
export { parseSession } from './parser.js';
export { loadConfig, resolveDirectory } from './config.js';
```

The `scan()` function is the primary API — it orchestrates config loading, filesystem scanning, and JSONL parsing, returning `ProjectInfo[]`:

```ts
export interface ScanOptions {
  /** Override ~/.claude location. Defaults to ~/.claude */
  claudeDir?: string;
  /** Max sessions per project. Defaults to no limit (all sessions). */
  limit?: number;
  /** Filter to projects matching this string (partial match on slug or directory). */
  projectFilter?: string;
}

export async function scan(options?: ScanOptions): Promise<ProjectInfo[]>;
```

Lower-level functions (`parseSession`, `loadConfig`, `resolveDirectory`) are also exported for consumers that want finer control — e.g. parsing a single known session file without scanning everything.

The CLI (`index.ts`) is just a thin wrapper:

```ts
// src/index.ts (simplified)
import { scan } from './lib.js';
import { formatTree } from './format.js';

const projects = await scan({ claudeDir, limit, projectFilter });

if (jsonOutput) {
  console.log(JSON.stringify({ projects }, null, 2));
} else {
  console.log(formatTree(projects));
}
```

### Step 1: Config Reader (`config.ts`)

1. Read `~/.claude.json` (or overridden path + `/../.claude.json`)
1. Parse as `ClaudeConfig`
1. Build a `Map<string, string>` from path-slug → real directory:
   - For each key in `config.projects`, compute the slug by replacing all `/` with `-`
   - Store `slug → realPath`
1. Export a `resolveDirectory(slug: string): string | null` function
1. Export per-project metadata (lastCost, etc.) keyed by resolved path

**Error handling:** If `~/.claude.json` doesn't exist or is malformed, log a warning to stderr and return an empty map. Never crash.

### Step 2: Active Session Detector (`active.ts`)

1. Read `~/.claude/sessions/` directory
1. Parse each `{pid}.json` file → `ActiveSession`
1. For each, check if PID is still running (via `process.kill(pid, 0)` in a try/catch)
1. Return a `Set<string>` of active session IDs

**Error handling:** If directory doesn't exist or any file fails to parse, return empty set. Never crash.

### Step 3: Scanner (`scanner.ts`)

Exports the main `scan(options?: ScanOptions): Promise<ProjectInfo[]>` function that orchestrates the full pipeline:

1. Load config via `config.ts` (for slug → directory resolution and per-project metadata)
1. Load active sessions via `active.ts`
1. Read `~/.claude/projects/` directory listing
1. Apply `--project` filter by partial-matching against slug or resolved directory
1. For each project slug dir:
   a. List contents, identify `.jsonl` files that match UUID pattern (`/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}\.jsonl$/`)
   b. Also identify session directories (UUID-named dirs) that have no sibling `.jsonl` file — these are orphaned sessions
   c. Get `fs.stat` mtime on each `.jsonl` for pre-sorting
   d. Sort sessions by mtime descending; if `limit` is set, take only top N before parsing
   e. For each session, check for `{session-id}/subagents/` directory:
      - Count `.jsonl` files for `subagentCount`
      - Read `.meta.json` files for `agentType` and `description`
   f. Parse each session JSONL via `parser.ts`
   g. For orphaned sessions (directory exists, no `.jsonl`): check `sessions-index.json` as a fallback to populate basic metadata (firstPrompt, messageCount, dates, branch)
   h. Mark `isActive` from the active sessions set
1. Resolve slug → directory via `config.ts`, falling back to `sessions-index.json`'s `originalPath`/`projectPath`
1. Attach `lastCost` from `~/.claude.json` per-project data
1. Return `ProjectInfo[]` sorted by `lastActive` descending

**Error handling:** `readdir` failures on individual project dirs → warn to stderr, skip that project. `stat` failures on individual files → skip that file.

### Step 4: Parser (`parser.ts`)

**Strategy: Simple streaming, full file read.** Use `readline.createInterface` on `fs.createReadStream` for each JSONL file. Process every line but keep per-line work minimal. No byte-seeking or tail optimization in v1 — keep it simple and correct first.

```ts
import { createReadStream } from 'node:fs';
import { createInterface } from 'node:readline';

export async function parseSession(filepath: string): Promise<SessionParseResult> {
  const rl = createInterface({ input: createReadStream(filepath) });

  const result: SessionParseResult = {
    slug: null,
    customTitle: null,
    firstPrompt: null,
    firstTimestamp: null,
    lastTimestamp: null,
    gitBranch: null,
    model: null,
    userMessageCount: 0,
    assistantMessageCount: 0,
    prLinks: [],
    summary: null,
    version: null,
    totalDurationMs: 0,
  };

  for await (const line of rl) {
    let entry: any;
    try {
      entry = JSON.parse(line);
    } catch {
      continue; // skip malformed lines silently
    }

    // Track timestamps from any entry that has one
    if (entry.timestamp) {
      if (!result.firstTimestamp) result.firstTimestamp = entry.timestamp;
      result.lastTimestamp = entry.timestamp;
    }

    // slug appears on assistant and system entries, NOT user entries
    if (entry.slug && !result.slug) result.slug = entry.slug;
    if (entry.gitBranch && !result.gitBranch) result.gitBranch = entry.gitBranch;
    if (entry.version && !result.version) result.version = entry.version;

    switch (entry.type) {
      case 'user':
        if (entry.isCompactSummary) break; // skip compaction artifacts
        if (entry.toolUseResult) break;    // skip tool results — not real human prompts
        result.userMessageCount++;
        // Capture first real user prompt
        if (!result.firstPrompt) {
          const content = entry.message?.content;
          if (typeof content === 'string') {
            result.firstPrompt = content.slice(0, 200);
          } else if (Array.isArray(content)) {
            const text = content.find((b: any) => b.type === 'text');
            if (text) result.firstPrompt = text.text.slice(0, 200);
          }
        }
        break;
      case 'assistant':
        result.assistantMessageCount++;
        if (entry.message?.model) result.model = entry.message.model;
        break;
      case 'system':
        if (entry.subtype === 'turn_duration' && typeof entry.durationMs === 'number') {
          result.totalDurationMs += entry.durationMs;
        }
        break;
      case 'custom-title':
        result.customTitle = entry.customTitle ?? null;
        break;
      case 'summary':
        result.summary = entry.summary ?? null;
        break;
      case 'pr-link':
        if (entry.prUrl && !result.prLinks.some((p: any) => p.url === entry.prUrl)) {
          result.prLinks.push({
            number: entry.prNumber,
            url: entry.prUrl,
            repo: entry.prRepository,
          });
        }
        break;
      // Skip: progress, file-history-snapshot, last-prompt, queue-operation, agent-name, saved_hook_context
    }
  }

  return result;
}
```

**Note on types at runtime:** Use `any` for parsed JSON and access fields directly. The vendored types are for dev-time type checking of the codebase itself, not for runtime validation of external data. The `switch` on `entry.type` provides runtime discrimination.

### Step 5: Subagent Metadata Reader (part of `scanner.ts`)

For each `.meta.json` file in `{session-id}/subagents/`:

Structure is `{agentType: string, description?: string}`. Examples:
- `{"agentType": "general-purpose"}`
- `{"agentType": "Explore", "description": "Analyze nelson repo thoroughly"}`
- `{"agentType": "general-purpose", "description": "Research gstack updated stats"}`

Read each `.meta.json`, extract `agentType` and `description` into `SubagentInfo[]`. Wrap in try/catch — if `.meta.json` is absent or unparseable, just skip that subagent's metadata (still count it from the `.jsonl` file).

### Step 6: Formatter (`format.ts`)

Terminal tree output using Unicode box-drawing characters (`├──`, `└──`, `│`).

### Step 7: CLI Entry (`index.ts`)

Thin wrapper over `lib.ts`. No business logic here — just arg parsing and output dispatch.

1. Parse args via `node:util` `parseArgs`
1. Handle `--help` and `--version` immediately
1. Determine `claudeDir` (default `~/.claude`, overridable with `--path`)
1. Call `scan({ claudeDir, limit, projectFilter })` from `lib.ts`
1. Dispatch to `formatTree()` (tree) or `JSON.stringify` (json)
1. Write to stdout

## Error Handling Policy

- **Malformed JSONL lines:** `JSON.parse` in a try/catch, skip the line silently. Common with partial writes from active sessions.
- **Missing `~/.claude.json`:** Warn once to stderr ("~/.claude.json not found, directory paths will not be resolved"), continue with null directories.
- **Missing `~/.claude/projects/`:** Print a clear error to stderr and exit 1 ("No Claude Code projects found at {path}").
- **Individual project/session read failures (ENOENT, EACCES):** Warn to stderr, skip, continue with remaining data.
- **Active sessions (files being written to):** No special handling needed — streaming readline handles this naturally.
- **Unexpected files in project dirs (e.g. `bridge-pointer.json`):** Ignore anything that doesn't match the UUID `.jsonl` pattern.
- **`sessions-index.json` missing or malformed:** Fall back to JSONL parsing. Never crash.

-----

## Performance Notes

- **Pre-sort by mtime:** `fs.stat` on `.jsonl` files before parsing. When `--limit` is set, only parse the N most recent.
- **Skip `progress` entries:** These are the main source of JSONL bloat. The switch/case simply doesn't handle them.
- **Subagent count from filesystem:** Just `readdir` + count `.jsonl` files, no JSONL parsing of subagent files.
- **No caching in v1:** Every run scans fresh. Caching can be added later if needed.
